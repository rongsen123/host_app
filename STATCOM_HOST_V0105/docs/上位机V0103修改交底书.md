# 单相STATCOM上位机 V0x0103 修改交底书

## 1. 修改目标与边界

本文件用于指导其他AI修改目录：

`F:\DSP\SST_PRJ\3_STATCOM_PI_PR\docs\statcom_host`

上位机只通过DSP的SCI-B通信，不直接访问CPLD。数据链路为：

```text
上位机主站 --SCI-B/Modbus RTU--> DSP从站2
DSP主站 --SCI-A/Modbus RTU--> CPLD从站1
```

本次上位机修改必须完成：

1. 适配DSP协议版本`0x0103`和29个输入寄存器。
2. 分开显示PC-DSP、DSP-CPLD接收端、CPLD接收端三层通信状态。
3. 将CPLD直流电压ADC码换算为工程电压，并同时保留原始码。
4. 将温度计数先换算为频率；没有传感器标定曲线前不得伪造摄氏度。
5. 正确处理STOP、START、清故障、CPLD复位、DSP复位、ADC重新校零。
6. 累计错误计数与“当前活动故障”分开显示，历史出现过错误不能永久显示成当前通信异常。

不要修改DSP和CPLD固件，不要增加PWM使能功能，不要绕过STOP安全联锁。

## 2. 串口与Modbus参数

| 项目 | 固定值 |
|---|---:|
| 串口 | 用户选择的USB-SERIAL端口 |
| 波特率 | 115200 bit/s |
| 数据格式 | 8N1 |
| 上位机角色 | Modbus RTU主站 |
| DSP从站地址 | 2 |
| CRC | CRC16/Modbus，初值`FFFF`，多项式`A001`，低字节先发 |
| 16位寄存器字节序 | 高字节在前 |
| 32位寄存器字序 | 高字在低地址，低字在高地址 |
| 周期轮询 | 建议100 ms一次 |
| 请求超时 | 100 ms |
| 同时未完成事务 | 只能有1个 |

周期轮询不能重复积压。一个请求未完成时，不得再发送第二个周期请求。STOP为最高优先级，但也要在当前串口帧事务结束或明确超时后发送，禁止字节级插帧。

## 3. 协议版本兼容

连接后先执行：

```text
FC04，起始地址0000，数量0001
```

- 版本`>=0x0103`：周期读取`0000-001C`，数量29。
- 版本`0x0101-0x0102`：兼容读取`0000-0016`，数量23，新增诊断项显示“不支持”。
- 不允许直接对旧固件读取29个寄存器，否则会收到Modbus异常02。

V0x0103周期请求的PDU含义：

```text
从站02，功能04，起始0000，数量001D
```

正常响应字节数为：`3 + 29*2 + 2 = 63`字节，响应字节计数字段应为`0x3A`。

## 4. DSP输入寄存器映射（FC04）

| 地址 | 数据 | 上位机处理 |
|---|---|---|
| `0000` | DSP协议版本 | 十六进制显示，例如`0x0103` |
| `0001-0002` | DSP运行时间ms | 组合为无符号32位 |
| `0003-0004` | ADC采样计数 | 组合为无符号32位 |
| `0005` | ADCINA0电网正半波原始码 | 原始count；现有暂定比例可保留 |
| `0006` | ADCINA2交流电流原始码 | 原始count |
| `0007` | 交流电流 | 有符号16位，`0.01 A/LSB` |
| `0008` | CPLD VDC瞬时ADC码 | 无符号12位原始count |
| `0009` | CPLD VDC 256点平均ADC码 | 推荐作为VDC工程值数据源 |
| `000A` | 温度脉冲计数/100 ms | `frequency_hz=count*10` |
| `000B` | CPLD状态位 | 按状态位表解析 |
| `000C-000D` | CPLD 32位锁存故障 | 高字在前 |
| `000E` | DSP判断的CPLD链路状态 | 按链路位表解析 |
| `000F` | PLL锁相标志 | 0/1 |
| `0010` | PLL频率 | `0.01 Hz/LSB` |
| `0011` | PLL输入有效 | 0/1 |
| `0012` | STATCOM调试状态 | 枚举显示 |
| `0013` | ADC零漂状态 | 0 IDLE、1 RUNNING、2 DONE |
| `0014` | DSP-CPLD累计综合错误低16位 | 包含CRC、格式、超时、异常、溢出 |
| `0015` | PC-DSP累计综合错误低16位 | DSP端看到的SCI-B错误 |
| `0016` | CPLD命令回显 | 0 STOP、1 START |
| `0017` | CPLD UART停止位错误计数 | 新增，低16位累计计数 |
| `0018` | CPLD Modbus CRC错误计数 | 新增，低16位累计计数 |
| `0019` | CPLD t3.5残帧超时计数 | 新增，低16位累计计数 |
| `001A` | DSP SCI-A硬件格式错误计数 | PE/OE/FE/BRKDT/RXERROR |
| `001B` | DSP SCI-A接收溢出计数 | 硬件FIFO或软件环形缓冲溢出 |
| `001C` | DSP等待CPLD回复超时计数 | 20 ms未收到有效回复 |

### CPLD状态`000B`

| Bit | 含义 |
|---:|---|
| 0 | DSP-CPLD链路在线 |
| 1 | CPLD ADC已有有效数据 |
| 2 | 温度计数已有有效数据 |
| 3 | CPLD存在锁存故障 |
| 4 | PWM健康；当前安全调试固件固定为0/未启用 |

### DSP-CPLD链路`000E`

| Bit | 含义 |
|---:|---|
| 0 | 在线 |
| 1 | 500 ms离线超时 |
| 2 | DSP历史上见过CPLD回复CRC错误 |
| 3 | DSP历史上收到过CPLD Modbus异常响应 |

Bit2/Bit3属于历史锁存提示，不能单独作为“当前链路断开”。当前在线应以Bit0、Bit1和数据更新时间共同判断。

### CPLD故障Bit10名称修正

`000C-000D`故障位Bit10必须从“UART帧格式错误”改名为：

```text
CPLD通信接收错误锁存（UART/CRC/残帧综合）
```

原因：该故障由CPLD的综合协议错误脉冲锁存。具体来源必须查看`0017-0019`的增量。

## 5. 工程量换算

### 5.1 CPLD直流电压

界面主显示使用`0009`平均ADC码，`0008`作为调试原始瞬时码。

实现可配置两点标定：

```python
vdc_v = vdc_gain_v_per_count * cpld_vdc_average + vdc_offset_v
```

配置文件建议字段：

```json
{
  "vdc_gain_v_per_count": 0.36034188,
  "vdc_offset_v": 0.0,
  "vdc_calibration_status": "PROVISIONAL"
}
```

`0.36034188=1475.6/4095`仅为原理图比例推算初值，必须通过至少两个实测电压点重新标定。上位机要同时显示：

```text
直流电压：xx.x V
原始平均码：xxxx count
标定状态：暂定/已标定
```

两点标定公式：

```text
gain=(V2-V1)/(C2-C1)
offset=V1-gain*C1
```

禁止只显示`91 V`；ADC码91不是91伏，按暂定比例约为32.8 V。

### 5.2 温度信号

`000A`是100 ms窗口内的脉冲数，不是摄氏度：

```python
temperature_frequency_hz = temperature_count * 10.0
```

例如计数418表示约4180 Hz。

在没有传感器“频率-温度”标定曲线前：

- 主界面显示`4180 Hz`。
- 次要位置显示`418 count/100ms`。
- 摄氏度字段显示`待标定`，不得直接显示`418 ℃`。

后续拿到标定数据后，配置成分段线性表：

```json
{
  "temperature_calibration": [
    {"frequency_hz": 0.0, "temperature_c": 0.0}
  ],
  "temperature_calibration_status": "UNCONFIGURED"
}
```

至少需要两个温度点；建议实际做3～5点并线性插值。

## 6. 保持寄存器与维护命令（FC03/FC06）

| 地址 | 写入值 | 功能与前提 |
|---|---:|---|
| `0100` | `0000` | STOP |
| `0100` | `0001` | START，仅调试回显，当前固件不会开启功率PWM |
| `0101` | `A55A` | 清除CPLD已消失的锁存故障；必须STOP |
| `0102` | `C33C` | 复位CPLD通信/采样/状态机；必须STOP |
| `0103` | `D55D` | DSP看门狗软复位；必须STOP |
| `0104` | `CA1B` | ADC电流零漂重新校准；必须STOP且当前不在RUNNING |

FC06成功响应必须与请求的从站、功能码、地址和值完全一致。不能只因收到任意8字节就提示成功。

### 清故障流程

1. 写`0100=0000`并确认DSP请求和CPLD回显均为STOP。
2. 写`0101=A55A`。
3. 收到完全一致的FC06响应后，不立即宣称故障已清除。
4. 继续轮询，确认`000C-000D`目标故障位消失。
5. 若物理故障输入仍存在，提示“清除命令已接收，但故障源仍存在”。

### CPLD复位流程

1. 确认STOP。
2. 写`0102=C33C`并校验完整回显。
3. 允许DSP-CPLD链路短暂离线，不将这段预期离线统计为用户可见故障。
4. 等待协议数据重新有效、心跳恢复递增；建议最多等待2 s。
5. 成功条件是重新在线，不只是FC06回显。

### DSP复位流程

1. 确认STOP。
2. 写`0103=D55D`。
3. DSP完整回复后执行看门狗复位，PC通信会短暂中断。
4. 暂停普通轮询300～500 ms，再重试版本寄存器。
5. 在2 s内看到运行时间和采样计数重新从小值增长才判定成功。

### ADC重新校零流程

1. 必须真实零电流、功率级STOP。
2. 写`0104=CA1B`。
3. 观察`0013`从RUNNING变为DONE。
4. 新固件采用采样队列逐点处理，通常约51.2 ms完成；上位机超时建议设为1 s。
5. 若一直RUNNING或出现ADC队列溢出，应提示校准失败，不显示成功。

## 7. 通信诊断页面要求

诊断页面至少分四块，禁止混为一个“超时/错误总数”。

### A. PC本地串口统计

来源为上位机自身：TX帧、成功RX帧、CRC错误、无响应超时、异常响应、平均/最大响应时间。

### B. DSP端PC-SCI-B统计

来源`0015`。这是DSP观察到的PC-DSP错误累计值，不是CPLD错误。

### C. DSP接收CPLD回复统计

来源：

- `001A`：硬件格式错误。
- `001B`：接收FIFO/环形缓冲溢出。
- `001C`：20 ms回复超时。
- `0014`：综合累计。

### D. CPLD接收DSP请求统计

来源：

- `0017`：UART停止位错误。
- `0018`：CRC错误。
- `0019`：不完整帧/t3.5超时。
- 故障Bit10：任一上述错误曾触发并被锁存。

所有16位累计计数计算增量时必须处理回绕：

```python
delta = (current - previous) & 0xFFFF
```

显示“累计值”和“最近5秒增量/错误率”两组数据。建议判断：

- 最近5秒增量为0：当前通信正常，历史累计仅灰色显示。
- 最近5秒增量>0：黄色告警。
- 链路离线或连续3次轮询失败：红色故障。

不要因为累计计数非零就永久显示红色。

## 8. 需要修改的上位机文件

### `protocol/register_model.py`

- `INPUT_QUANTITY`由23改为29，并保留旧版本23寄存器兼容。
- 解析`0017-001C`。
- Bit10重命名。
- 增加VDC可配置换算和温度频率换算。

### `communication/serial_worker.py`

- 连接后先读版本，再选择23或29寄存器。
- `parse_input_block()`的期望数量不能写死23。
- 仿真器协议版本改为`0x0103`并生成29个寄存器。
- 保持单事务、周期请求不积压。
- 每个维护命令校验精确FC06回显。

### `ui/main_window.py`

- VDC卡片单位从`count`改为`V`，旁边显示原始count和标定状态。
- 温度卡片先显示`Hz`，摄氏度显示“待标定”。
- 通信诊断按第7节拆分。
- Bit10改名。
- 清故障/复位/ADC校准按照状态回读决定最终成功，不以写响应代替完成状态。

### `storage/logger.py`

CSV新增：

```text
cpld_vdc_V
cpld_vdc_raw
cpld_vdc_average
temperature_frequency_Hz
temperature_count_100ms
cpld_uart_error_count
cpld_crc_error_count
cpld_incomplete_frame_count
dsp_scia_format_error_count
dsp_scia_overflow_count
dsp_cpld_timeout_count
```

原始值和工程值必须同时记录，便于后续重新标定。

### `tests/test_protocol.py`

至少增加：

1. 版本`0x0103`读取29寄存器、响应63字节。
2. 旧版`0x0102`回退读取23寄存器。
3. `0017-001C`解析测试。
4. 16位计数器回绕增量测试。
5. VDC两点标定换算测试。
6. 温度count到Hz换算测试。
7. FC06错误地址/错误值/异常响应不得判成功。
8. CPLD复位和DSP复位必须通过后续状态变化验收。

## 9. 验收标准

1. 真实串口115200、8N1连接DSP从站2，能稳定读取29寄存器。
2. 主界面VDC不再把ADC码直接当伏特显示。
3. 温度不再把脉冲计数直接当摄氏度显示。
4. 可以明确区分：PC-DSP错误、DSP接收溢出、CPLD UART错误、CPLD CRC错误、CPLD残帧错误。
5. 历史累计错误停止增长后，界面恢复“当前正常”，累计值仍保留。
6. STOP、清故障、CPLD复位、DSP复位、ADC重新校零均有命令响应和状态回读双重确认。
7. 仿真模式和真实串口模式使用同一寄存器模型。
8. 所有协议单元测试通过后重新打包EXE。
